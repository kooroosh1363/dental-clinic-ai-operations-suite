# Personas and user stories

## Maya — clinic administrator

Needs one view of daily capacity, risky follow-ups, unresolved decisions and an accountable history.

- As an administrator, I can resolve sensitive actions so automation cannot silently commit them.
- As an administrator, I can inspect audit events so ownership is visible.
- As an administrator, I can see operational metrics without exposing unnecessary clinical detail.

## Leo — receptionist

Coordinates patient requests and schedules under time pressure.

- As a receptionist, I can turn an existing patient into an appointment through a validated form.
- As a receptionist, I can search patients and appointments quickly.
- As a receptionist, I can ask policy questions and receive cited, approved answers.

## Jordan — prospective patient

Wants to request care without assuming that a form submission is a confirmed booking.

- As a patient, I can state a preferred date and service with explicit consent.
- As a patient, I receive a clear review message rather than a false confirmation.
- As a patient with urgent language, my message is escalated to a human without an automated diagnosis.

## Priya — technical reviewer

Needs to distinguish working implementation from architecture theatre.

- As a reviewer, I can run the system without paid APIs.
- As a reviewer, I can inspect migrations, seed data, tests, workflow exports and failure paths.
- As a reviewer, I can see limitations and production prerequisites stated plainly.
